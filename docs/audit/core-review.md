## Additional real regressions found before final artifact

- MCP/Skill command expansion injected English instruction text that could be interpreted as an App action (including destructive intentions). The runtime now retains explicit `/mcp` or `/skill` provenance through one shared routing guard. Four reproduced negative cases changed from RED to GREEN; capability command focused tests are actual evidence, not a live external MCP claim.
- `preferences.reset` wrote the real appearance defaults, then incorrectly compared its `expected_revision` control argument to a preference key and returned a failed receipt. The new real Gateway/AppTool test reproduced this. Dispatcher now checks actual APPEARANCE defaults and excludes revision control metadata; a no-op reset regression separately proves unchanged appearance cannot pass.
- ContentPage deleting a recent import retained its selected query ID long enough to GET the deleted record and produce a browser 404. A focused UI test reproduced GET-after-DELETE. Selection and queries now clear/invalidate together; the full frontend unit rerun passed 51 tests in 14 files (10.20 s). Real browser rerun is independently recorded in browser-e2e/report.json.
- Agent file import previously referenced a nonexistent attachment Service behind a restricted gate. It now explicitly raises `capability_unavailable`; direct handler and Gateway denial tests verify the boundary. Existing UI uploads still use InboxService.import_item. A session-bound Agent attachment grant protocol has not been implemented.

## Minimal explicit-AI closure

Explicit AI import/classification templates previously forced use_ai=False or synchronously invoked classification. They now preserve the request and reuse the owned durable worker, returning pending/job_id. The 96 affected tests and complete 570-pass backend run verify persisted outcomes. Two independently reproduced edge cases were fixed: retry resets only same-revision failed archival intent; content and successful archive receipt commit in one original Service transaction, so revision+1 from a manual move cannot be misreported as worker success. No new worker, business Service or scheduler was added.
