# 游客演示版、共用 Wiki 与首次使用引导

> 历史设计：用户随后指定参考 ForceTrack 的首次遮罩导览，并明确不要独立说明文档。当前实现已移除 Wiki 页面与 Markdown 正文，改为可跳过、可重播的逐页功能介绍，不再要求实际业务操作来推进引导。以下原设计保留供追溯，以最新用户要求及验收记录为准。

日期：2026-10-16

分支：`codex/web-demo-deployment`

状态：用户已评审通过并授权实施；功能已实现，验证结果见 `docs/audit/web-demo-guide-2026-10-16.md`。补充要求“引导 Wiki 要将每个功能都简单介绍一下”已落实为 83 项功能简介。

## 1. 目标与约定

让首次接触息流的人无需安装、登录或配置模型，就能体验主要信息整理流程，并知道应用有哪些功能、如何开始使用。

用户已确认的范围：

- 做一个游客演示版，预置示例资料，支持收集、归类、检索、计划与演示问答。
- 提供 Web 和桌面端共用的 Wiki，包含功能介绍、操作步骤和进入功能的链接。
- 提供可跳过、可重新打开的首次使用引导。
- 沿用息流现有界面风格，在当前任务分支完成。

“同步两端”在本次任务中指两端共享功能说明与引导代码、随版本共同更新。用户的个人资料继续使用现有存储方式，不增加跨设备账号或云端数据同步。

成功标准：访问静态演示站即可完成“收藏资讯 → 整理资料 → 引用提问”；本地 Web 和桌面正常模式可以打开同一套完整 Wiki 和操作引导；演示操作不访问或改写真实后端资料。

## 2. 路线选择

| 路线 | 取舍 | 决定 |
| --- | --- | --- |
| 共用真实界面，演示模式使用浏览器数据层 | 主要页面保持一致，可静态部署；需覆盖页面的数据请求 | 采用 |
| 复制一套独立演示界面 | 初期简单，但功能与指引容易漂移 | 不采用 |
| 直接公开现有 Python 实例 | 有真实 AI，但需先解决用户隔离、工具限制和成本控制 | 留作后续真实 AI 试用任务 |

本次交付独立的静态演示构建产物与发布说明。云平台账号、域名和公网发布不在本次实现范围内；构建后的文件可用于部署，不代表已上线。

## 3. 代码接入与模式边界

### 3.1 保留现有应用结构

继续复用 `web/src/app/App.tsx` 的路由、页面与 QueryClient，以及现有 API 数据类型。增加演示模式、帮助页面和引导组件，不复制业务页面，不改动 Rust 桌宠实现。

演示模式通过独立构建配置启用，提供明确的 `build:demo` 和本地预览命令；正常 `build` 保持真实 API 行为。演示构建与正常构建输出不同目录，避免桌面打包误用演示产物。

发布目标首先是独立域名的根路径。构建说明包含静态托管的 SPA 回退规则，保证 `/guide/...` 等地址直接打开和刷新可用。发布到子路径需要相应设置资源 base 和 Router basename，本次不默认支持任意部署子路径。

### 3.2 显式的数据请求入口

增加共用的应用数据请求函数，正常模式调用原生 `fetch`，演示模式调用本地演示处理器。将应用内 API 请求接入该函数，至少覆盖：

- `web/src/lib/api.ts`：聊天、模型和能力读取。
- `web/src/lib/workspace-api.ts`：Feed、资料、文件夹、任务和设置。
- `web/src/lib/preferences.ts`：个人与外观偏好同步。
- `web/src/features/today/background.ts`：背景与外观资源。
- 其他实际访问 `/api` 的资源入口，通过源码搜索和浏览器网络检查补齐。

不替换全局 `window.fetch`，也不使用开发服务器代理、Service Worker 或真实 API 作为演示的回退。未支持的演示请求返回明确的演示限制提示，禁止静默访问后端或假装成功。

模式选择在模块初始化时保持稳定；不提供会把现有真实页面原地切到演示数据的运行时开关。

## 4. 演示数据和交互

### 4.1 预置数据

内置一套完整且相互关联的示例：若干 Feed、Inbox 笔记和链接、已归档的 Knowledge 资料与文件夹、日/周/目标计划，以及一段演示助手会话。

示例覆盖“发现 → 收集 → 整理 → 提问 → 行动”，名称和内容具有实际可读性。资讯标为示例，不声称是实时抓取；不包含开发者资料、真实配置、密钥或私人会话。

### 4.2 支持范围

| 模块 | 演示中的实际行为 |
| --- | --- |
| Today | 浏览主页，快速收集文字或链接，进入演示聊天 |
| Feed | 筛选、搜索、手动添加和编辑、隐藏/恢复、收藏到 Inbox；刷新保留示例语义 |
| Inbox | 新建文字和链接、编辑、删除、选择和批量归类、按示例规则整理 |
| Knowledge | 创建和编辑文件夹、移动资料、标签与中文关键词检索、打开详情 |
| Assistant | 新建/切换/删除会话，引用资料，接收明确标注的模板回复，停止未完成的演示输出 |
| 个人计划 | 创建、编辑、完成和删除日/周/目标计划 |
| 设置 | 编辑演示内的个人资料与主题；查看能力限制和数据保存说明 |
| Wiki | 搜索、阅读全部功能说明，跳转到可用功能；桌面专属功能显示平台标识 |

AI 元数据整理、实时资讯抓取、真实网页正文抓取、PDF/DOCX 解析、任意文件上传、后台自动任务执行、命令执行和第三方 MCP 在演示中不执行。相关操作在入口给出具体说明及可用替代步骤，不用未实现的接口制造成功状态。用户粘贴的链接可以本地保存，但不抓取内容。

演示的原件入口不生成失效的 `/api/...` 下载地址；文本资料可打开其已保存正文，涉及原始文件的能力引导到 Wiki。

### 4.3 演示回复

助手使用可预期的本地模板回复，优先覆盖引导中的三类问题：介绍息流能力、总结当前引用资料、解释如何归类和安排下一步。

每条模板回复都明确标注“演示回复”；引用来自当前演示数据，不虚构已读取的外部资料。没有对应模板的问题说明演示范围并给出示例问题。助手建议不会声称已执行未发生的资料或计划修改。

支持逐段显示和停止。停止或重置后，旧的异步输出不能继续写入新的状态或已删除的会话。

### 4.4 保存、隔离和重置

- 用带 schema 版本的独立演示命名空间保存 JSON 状态，与正常应用偏好、布局和引导状态分开。
- 页面刷新后保留当前浏览器的演示修改。不同浏览器或不同设备各自独立；同一来源的多个标签页共享浏览器存储，不宣称它们是独立用户。
- 演示状态设总量上限，达到上限时提示删除或重置；本次不把二进制附件存入 JSON。
- 存储不可用时明确提示“本次体验仅在当前页面保留”，使用内存继续；无效存档可恢复到预置示例并提示用户。
- 状态写入使用递增修订号；检测到其他标签页的新修订时读取新状态，旧修订写入被拒绝并提示重试，避免静默覆盖。
- 重置前说明会清除演示内的修改。确认后取消演示流、恢复示例、清空演示查询缓存和引导进度，再重新显示起始步骤。
- 不清除正常模式存储，不调用真实 API，也不触发 Tauri 原生写入。

## 5. Wiki：同一内容供两端使用

### 5.1 内容来源与入口

以 `docs/wiki/` 中的 Markdown 为唯一正文来源，前端直接编译这些文件。用轻量目录索引记录文章 slug、标题、摘要、分类、平台和关联路由；不引入远程内容服务。

提供 `/guide` 和 `/guide/:slug` 路由，在侧栏底部保留带可访问名称的“使用指南”入口，首次欢迎面板和各模块说明链接到具体文章。

Wiki 的功能跳转使用已有应用路由。正常 Web 和桌面均在应用中打开；演示版的桌面专属操作跳转到说明，不触发不存在的原生能力。

### 5.2 首版文章清单

1. 快速开始：产品用途、三个步骤体验、演示与正常模式的区别。
2. 功能地图：Today、Feed、Inbox、Knowledge、Assistant、计划、设置之间的关系。
3. Feed：来源、筛选、收藏、手动资讯、Ask AI。
4. Inbox：文字、链接、文件收集、处理状态、编辑与批量归类。
5. Knowledge：文件夹、标签、检索、资料引用和原件。
6. Assistant：多会话、模型切换、引用资料、思考过程、停止、操作确认。
7. 个人计划：日、周、目标计划与完成状态。
8. 模型配置：提供商、地址、模型和 Key；真实模式与演示限制。
9. 自动任务与扩展：创建与运行条件、Skill / MCP 的用途和配置前提。
10. 外观与桌宠：主题、背景、布局、Windows 独立桌宠、Live2D 资源条件。
11. 数据与备份：正常 Web 的服务端数据、浏览器偏好、桌面数据目录、升级备份和演示重置。
12. 常见问题：模型连接失败、资讯未更新、导入失败、扫描 PDF、停止后的实际状态。

每篇正文包含“能做什么、如何操作、结果在哪里、使用条件或限制、下一步”。文案以现有源码和功能记录为依据，不把安装包、真实模型调用或新增功能写成已完成验收。

每项面向用户的功能都必须有单独的小节和简短介绍，不能只介绍模块名称。每个小节先用两三句话说明用途、入口和基本操作，再补充限制或详细步骤。功能目录覆盖页面内的细分操作和助手快捷命令，桌面专属、需联网和演示不可用的能力分别标记；通过功能清单检查简介与正文的对应关系。

### 5.3 检索与阅读

在本地检索文章标题、摘要和正文；返回文章标题及命中片段，搜索无结果时提供清空搜索和返回目录的操作。

桌面宽度采用目录与正文布局；窄屏将目录收起为可操作导航，正文不横向溢出。保留清晰标题层级、锚点、键盘焦点和深色主题。Markdown 禁止直接执行原始 HTML；外链遵循现有安全 URL 规则。

桌面安装包内置相同版本的正文，离线可读；更新指引内容通过更新应用版本完成，不依赖在线 Wiki 才能显示帮助。

## 6. 首次引导与功能发现

### 6.1 进入方式

首次进入主工作区时展示欢迎面板，提供“开始快速上手”“浏览所有功能”“稍后再看”。不挡住启动动画、不强制用户完成教程。

演示版显示持续可见且轻量的演示标识、数据保存说明与重置入口；正常模式不出现演示标识。

用户完成或跳过引导后保存版本化进度。帮助中心可以随时重开。演示与正常模式各自记录进度；首次引导不会因为一次普通版本更新重复弹出。

### 6.2 三步主要流程

1. **收藏资讯**：解释 Feed 的作用并跳转 Feed，用户将一条资讯保存到 Inbox。
2. **整理资料**：打开 Inbox 中该资料，添加标签并归档到 Knowledge，展示实际位置。
3. **引用提问**：在资料上选择 Ask AI，进入带引用的 Assistant；演示模式提供示例问题和演示回复，正常模式提示配置模型后再发送。

步骤使用真实操作结果判断完成，切换页面本身不算完成。允许返回、跳过、关闭和继续；遇到资料被删除时提供重新选取资料的动作。

正常模式的引导不自动写入示例资料、不自动调用模型、不自动完成归档。操作仍由用户在现有界面明确执行。

引导优先采用页面内步骤面板，避免依赖坐标的遮罩或脆弱的 DOM 查找。各主要模块提供短说明及“查看指南”链接，帮助用户发现三步流程之外的计划、自动任务和桌宠。

## 7. 视觉方向与研究依据

优先锁定现有息流界面作为视觉目标：复用已有字体、浅/深色 token、细边框、黑色主操作、图标与空间密度，不重做首页或引入新视觉主题。

本次尝试 Refero 的 styles、screens、flows 查询均返回 `NO_SUBSCRIPTION`，不能把未取得的结果列作参考。补充使用本地 Refero craft/copywriting 指南及公开官方帮助中心：

- [Notion Help](https://www.notion.com/help)：按功能组织文档，并有新手入口。
- [Notion：创建第一篇页面](https://www.notion.com/help/create-your-first-page)：围绕具体操作提供入门步骤。
- [Obsidian Help](https://obsidian.md/help/)：以基础操作序列帮助第一次使用的人开始。

| 决策 | 来源 | 采用的规则 | 理由 |
| --- | --- | --- | --- |
| Wiki 复用现有视觉 token 和组件 | 当前应用、用户确认 | 保留画布、字体、配色角色与密度 | 帮助属于当前应用的一部分 |
| 目录与文章分离，可搜索 | 官方帮助中心的功能分类、用户 Wiki 需求 | 先定位任务，再读步骤 | 支持快速查找与深入阅读 |
| 三步引导、可跳过、可重开 | 用户确认、官方入门流程 | 用具体任务说明结果 | 让用户完成一条实际工作流 |
| 演示标识和限制紧邻操作 | 用户确认、copywriting 指南 | 说明条件和可行的下一步 | 防止将模板回复理解为真实 AI |
| 可访问名称、焦点、减少动态效果 | 当前应用、本地 craft 指南 | 保留键盘与辅助技术访问 | 两端采用同一套基本交互标准 |

## 8. 验证与交付标准

### 自动化验证

- 演示模式的请求不触发真实 `fetch('/api...')`；未知请求明确失败。
- 演示数据可以收藏、编辑、归档、检索、创建与完成计划；刷新保留，重置恢复。
- 破损数据、存储不可用、修订冲突、删除会话及流取消有明确结果。
- Wiki 全部目录条目有正文，slug 唯一，内部路由有效；搜索、无结果和深链接可用。
- 引导进度由实际操作推进，跳过/继续/重开有效；正常模式不自动写资料或调用模型。
- 正常构建保持原有 API 与桌面桥接行为；演示构建不包含真实配置和运行数据。

### 构建与交互验证

- 运行相关前端测试、lint 和两种构建；受影响的既有测试需要通过。
- 将演示产物用独立静态服务启动，关闭 Python 服务，浏览器完成主要流程；检查没有 `/api` 网络请求或控制台异常。
- 检查桌面宽度、窄屏、键盘操作、深色模式和减少动态效果。
- 通过正常本地 Web 验证共用 Wiki 和引导，并检查 Tauri 环境的显示与桥接边界。未实际完成的 Windows 原生交互验证必须明确记录，不以单元测试替代。
- 现有桌宠、版本号及其他任务的未提交改动保留；仅对本任务文件进行提交。

### 交付物

1. 静态游客演示构建模式、预置数据和演示限制说明。
2. 仓库内可维护的 Wiki 正文与两端共用阅读页面。
3. 首次欢迎、三步引导、功能帮助入口和可重开进度。
4. 演示构建/预览/静态部署说明及验证记录。

本设计评审通过后再编写详细实现计划。真实 AI 后端、账户体系、跨设备同步和外部发布仍作为独立后续任务。
