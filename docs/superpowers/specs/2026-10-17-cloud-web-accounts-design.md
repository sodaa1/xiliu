# 完整网页端：账号、游客与模型试用设计

日期：2026-10-17。状态：待用户审阅；尚未实现。

## 已确认的目标

- 将现有演示扩展为连接真实后端的公开多用户网页应用。
- 本次包含注册、登录和每人独立资料，为未来桌面账号关联与同步预留接口。
- 保留无需登录的游客体验。
- 登录用户可配置自己的模型 API；站点另外提供每个账号累计 5 次公共模型试用。
- 当前没有服务器，先完成并验收可部署包，再选择托管；本次不声称已经上线完整服务。
- 保留现有 GitHub Pages 游客演示和 Windows 桌面版。

## 方案选择

推荐采用 Docker 部署 Python/FastAPI 后端及现有前端，按账号分配独立工作区。现有服务依赖本地 SQLite、附件目录、Runtime 与后台调度，采用持久卷可以复用大部分业务实现。

另外两种方式：直接改为 Workers + 云数据库/对象存储，需要迁移持久化、后台任务和运行时依赖；每账号独立容器可以提供更强的进程隔离，但需要额外的容器编排和资源管理。二者均不作为首版部署包的默认方案。

Cloudflare 可继续管理域名和 HTTPS/CDN 接入。GitHub Pages 保留静态演示；完整版需要能够运行容器并提供持久存储的环境。首版为单实例部署，不承诺直接增加多个应用进程即可扩容。

## 用户流程

1. 未登录访问完整站点时，显示登录、注册和“先体验一下”入口。
2. 游客进入独立演示构建，使用当前示例资料、浏览器内存储、演示回复和首次引导，不请求正式业务 API，也不占用公共模型额度。
3. 注册采用用户名和密码，登录后获得稳定的用户 ID 和工作区 ID。首版不依赖邮件或短信服务；提供管理员重置密码命令，不显示虚假的邮件发送结果。
4. 登录后的真实工作区初始为空。演示与正式资料分别保存，登录不会自动把示例数据导入正式资料；退出后仍可返回原游客体验。
5. 用户可选择公共试用模型，或在模型设置中配置自己的 API。界面说明当前使用来源及剩余试用次数。
6. 退出登录或会话失效时，中止流式请求并清空该账号的查询缓存、敏感临时状态；再次登录其他账号不能看到前一账号的资料。

## 本次提供的网页能力

保留真实的资讯收藏与整理、收件箱导入和附件、知识库与检索、聊天与引用、今日/个人计划、偏好设置和按账号隔离的自动任务。模型、搜索和外部数据源仍需要相应配置，未配置时如实提示。

浏览器不提供原生桌宠独立窗口、系统托盘或本机窗口控制；角色预览可以保留。公开服务中的工具权限由服务端限定：首版不向普通账号开放服务器命令执行、任意文件系统访问、安装软件、上传执行任意 Skill 或启动任意 stdio MCP。已有网页业务操作继续通过同一组受权限控制的服务执行；需要这些本机能力时使用桌面版。

## 服务结构与隔离

- 增加独立云端入口和配置。现有本机/桌面入口继续采用本机访问限制，不通过伪造 Host 或全局放开中间件来部署。
- 云端入口同源提供正式前端、公开游客静态目录、身份接口和经过认证的业务接口。
- 所有正式业务请求都先解析服务端会话，再获得对应工作区的服务对象；不接受客户端指定另一个用户的工作区，不在请求之间修改全局 `app.state` 来切换用户。
- 身份数据库存放账号、会话、试用额度和管理员配置。工作区目录采用服务端生成的不可变 ID，保存各自的业务 SQLite、附件、检索索引、模型配置和自动任务记录。
- 后台任务和流式聊天持有明确的工作区上下文，不能因用户登出、缓存淘汰或其他用户请求而切换资料。资源池具有容量限制，使用中的服务对象不能被关闭。
- 云端的模型设置不继承服务器进程中的个人模型 Key，不能把管理员公共模型配置作为某个用户的自有连接返回。
- 用户 Key 使用成熟加密库加密保存，主密钥由部署者在运行环境配置，不进入源码、镜像、前端、日志或 API 响应。API 仅返回掩码及是否已配置。
- 浏览器缓存、偏好及素材缓存按账号/工作区区分；不能只隔离服务端数据库而继续共用已有本地缓存键。

## 登录与请求保护

- 密码使用成熟的密码哈希库保存；不存储明文或可逆密码。
- 浏览器采用可撤销的服务端会话和 HttpOnly Cookie；生产环境要求 HTTPS、Secure Cookie 和明确的会话过期时间。
- 写请求校验来源与 CSRF；部署域名和允许来源采用精确配置，不使用通配放行。
- 登录、注册、公共试用、上传和导入具有速率、并发及大小限制。持久化必要限额，重启不重置试用额度。
- 用户猜测其他账号的会话、附件、任务、归档作业或确认 ID 时，不能读取、修改、停止或下载其资料。
- 网络出口同时覆盖模型接口、链接抓取、搜索与 MCP：阻止服务器内网、回环、链路本地/元数据地址访问，处理重定向和 DNS 解析风险。普通用户不能把自定义 URL 当作访问宿主机的代理。
- 公开云模式采用服务端不可由用户修改的工具策略，覆盖 HTTP 操作、聊天、后台任务与委派路径；不能只隐藏前端按钮。

## 公共模型试用规则（建议默认值）

- “5 次试用对话”按每个账号累计 5 次真实 AI 回复计算，跨会话累计，不是 5 个无限消息的聊天窗口；退出、换浏览器和重启均不重置。
- 游客仍为演示回复，注册用户才可消耗公共试用次数。选择用户自己的模型时不扣公共试用次数。
- 发起真实模型请求前，服务端原子预留次数；并发发送不能超额，同一请求重试不能重复扣次。
- 模型未开始处理的验证、连接或配置失败返还次数；已经开始生成后手动停止仍计次，界面明确说明。
- 服务器限制单次输入、输出长度、单轮模型调用次数、并发和全站每日试用总量。账号各有 5 次不等于全站开销无限；达到站点上限时提示稍后再试或配置自己的 API。
- 公共模型凭据由管理员部署时单独配置；未配置时不显示可用试用，也不返回伪造成功结果。
- 使用本地模拟提供方验证成功、失败、取消、并发、重试和重启，不要求开发阶段提供真实 Key 或产生实际模型费用。

## 为桌面同步保留的边界

账号 ID、工作区 ID 和业务记录 ID 稳定；记录修改保留版本与删除信息，为后续增量同步提供基础。服务层与认证协议不依赖浏览器页面，后续可增加桌面客户端登录凭证。

本次不宣称实现桌面端登录、离线变更上传、冲突合并、跨设备附件同步或旧桌面资料自动迁移。这些作为下一阶段独立验收；仅新增账号并不等于已经完成跨端同步。

## 部署交付

- 多阶段 Dockerfile：Node 构建正式前端与带前缀的游客演示，Python 运行层仅安装生产依赖。
- Docker Compose、配置示例、密钥生成说明、持久卷、健康检查、初始化/重置账号和备份恢复指引。
- 默认不上传或打包开发者 `.env`、`.xiliu`、数据库、日志、Windows EXE 或模型密钥。
- 反向代理提供 HTTPS，并支持现有 NDJSON 流式聊天与停止，不缓存整段响应。
- 本机未发现 Docker 命令：优先通过 GitHub Actions 构建镜像并运行容器集成验收，不擅自安装 Docker Desktop。
- 选择服务器与域名后，再进行真正的公网部署、HTTPS 和真实模型连接验收。

## 必须通过的验收

1. 两个账号在同一服务器并发操作，所有资料、聊天、附件、计划、偏好和后台作业隔离；跨账号请求被拒绝。
2. 未登录不能调用正式 API；过期、注销、错误来源和 CSRF 请求均按预期处理。
3. 游客无需登录完成主要体验；演示不触发正式 API，登录不会混入示例数据。
4. 浏览器在账号 A、退出、账号 B 之间切换，不残留 A 的资料、模型状态或流式回复。
5. 用户自有 Key、管理员试用 Key 和服务端环境变量互不混用，API/日志不泄漏明文。
6. 试用第 5 次、超额第 6 次、并发抢占、失败返还、停止、重试和重启均使用模拟模型验证。
7. 网页聊天、自动任务和直接 HTTP 操作不能绕过云端工具及网络出口策略。
8. 容器重启后账号、资料、附件和额度保留；持久卷备份可恢复，镜像不含开发者资料。
9. 完整后端、前端和相关桌面回归通过；现有 GitHub Pages 演示继续可用。
