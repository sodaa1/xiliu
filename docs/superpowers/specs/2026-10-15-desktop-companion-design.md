# 息流角色展示与 Windows 常驻桌宠设计

日期：2026-10-15。状态：概念与双形态用途已经用户确认；本书面规格待评审，尚未进入业务代码实施。

## 1. 目标与已确认方向

用户希望在不先进入主工作台的情况下，看到任务的简单进展、快速开始对话，并快速打开 Inbox 新建卡片收录内容。桌宠在 Windows 桌面常驻，主窗口最小化后继续可用。

用户已确认保留二次元角色的两种形态：正常比例角色融入桌面应用页面，Q 版作为桌宠。正常比例和 Q 版属于同一角色，保留银紫短发、星形发夹、白色紫衬披肩及深色服装。角色名称暂用内部标识 `star-spirit`，不把预览时提出的名字视为用户已定名。

“桌面页面”在本规格中按息流 Today 首页理解。这是页面位置的实施默认值；不修改 Windows 壁纸或系统桌面背景。

成功标准：用户可从桌宠一次展开快捷面板，开始新会话或打开独立收录窗；收录保存后得到明确反馈；桌宠显示实际任务状态；主窗口最小化、隐藏和恢复不造成重复发送或中断对话。

## 2. 方案选择与范围

采用现有 Tauri 2 桌面壳中的独立伴随窗口，复用 React、ChatProvider 和 Inbox 服务。

| 方案 | 取舍 |
| --- | --- |
| 轻量伴随窗口，主窗口统一管理对话（选用） | 独立桌宠与收录窗提供快捷入口，主窗口复用现有模型设置和执行逻辑；需要跨窗口同步 |
| 仅跳转主窗口的启动器 | 改动较少，但不能在独立小窗完成收录 |
| 桌宠内独立完整聊天系统 | 面板可独立承载全部会话，但引入第二套对话流和同步负担，超出首版需要 |

首版范围包含 Today 角色欢迎区、桌宠窗口、快捷对话、独立 Inbox 收录窗、托盘和退出流程、状态同步，以及 Q 版 Live2D 的素材与渲染接口。

语音、摄像头跟踪、桌面漫游、换装、角色市场、自定义模型导入和全局快捷键留待后续需求。首版不新增模型调用来生成桌宠摘要。

## 3. 视觉依据与资源

主参考为用户已认可的二次元角色设定图和项目现有界面。Refero 在线研究返回 `NO_SUBSCRIPTION`，因此采用其技能自带的动效、表单与焦点规范，并沿用本项目品牌。没有取得可用的在线 Refero 风格或流程样本。

参考锁：

- 保留角色的银紫短发、四芒星发夹、白紫披肩、深色衣裙及鞋靴，正常比例与 Q 版保持身份一致。
- 沿用息流品牌紫 `#7773e9`、现有正文与表面变量、现有中文字体及深浅主题。
- 正常比例采用清晰的 2D 立绘；Q 版采用约 2.5 头身，用表情和小动作表达状态。
- 功能面板沿用现有按钮、输入框和焦点表现；紫色承担主操作与选中状态，不铺满页面。
- 不把角色图作为文字背景；不增加持续的大幅晃动、闪烁和覆盖业务的装饰。

| 决定 | 依据 | 用途 |
| --- | --- | --- |
| 正常比例与 Q 版同时保留 | 用户本轮明确要求 | 首页角色展示与 Windows 桌宠分别使用 |
| 首页立绘放在欢迎区右侧 | Today 现有问候语、快捷提问与内容区结构 | 建立伴随感并保留简报、待办的操作空间 |
| 气泡显示一两句真实进展 | 用户要求、ChatProvider 已有 `status/steps` | 用户可扫读当前任务，不展开完整原始推理 |
| 状态反馈短而克制 | Refero 自带 motion 指南 | 面板约 160–240ms 过渡；动画服从减少动态效果设置 |
| 保存失败保留输入 | 现有 CaptureDialog 与 craft-details 指南 | 避免随手收录时丢失内容 |

资源保存在 `docs/reference/desktop-companion/`：

- `character-board.png`：已认可的完整角色设定参考。
- `standing-source.png`：正常比例独立透明 PNG，首页立绘源素材。
- `chibi-source.png`：Q 版独立透明 PNG，桌宠与拆层参考源素材。
- `asset-notes.md`：生成方式、提示词、使用边界与来源。

上述 PNG 是扁平源素材，不是 PSD 拆层稿，也不是已经制作完成的 Live2D 模型。实施时将经过验收的运行资源放入前端静态资源目录，不让产品依赖本机 Codex 生成目录。

## 4. Today 首页中的正常比例角色

在 Today 顶部设置欢迎区：左侧组合现有问候语、快速对话和 Inbox 新建入口，右侧展示正常比例角色。现有今日简报、Inbox 数量和待办仍在下方可操作区域。

宽屏下立绘显示高度约 280–360 CSS px，保持原图比例，不拉伸。为立绘预留固定布局空间，避免图片加载后挤动输入框。窄屏下转为上下布局并缩小立绘；信息密集时可隐藏装饰立绘，保留所有操作。图片自身不接收鼠标事件，也不覆盖控件。

欢迎区的文案与实际数据对应，不编造今日任务或角色自动观察到的行为。完整角色展示首版可以使用静态立绘；用户确认的 Live2D 目标优先用于桌宠。正常比例 Live2D 不列为首版交付前提。

## 5. 窗口与生命周期

窗口职责：

- `main`：保留现有工作台、ChatProvider、模型设置和运行中会话，作为前端对话流唯一所有者。
- `companion`：透明无边框的 Q 版桌宠和快捷面板，默认不在任务栏单列，支持拖动与记忆位置。
- `capture`：按需打开的独立收录窗，初始约 440×560 CSS px，允许调整大小及滚动。

按用户追加要求，默认桌宠角色高度为 96 CSS px，可在 72–128 CSS px 内调整；气泡和面板避开当前显示器边缘。透明窗口随可见内容收缩，避免大块透明区域截获桌面点击。跨显示器移动、DPI 改变和移除外接显示器后，将位置约束到当前可用工作区。

启用桌宠时，主窗口最小化或关闭到托盘不销毁主 WebView，也不关闭本地服务；关闭收录窗或隐藏桌宠只影响对应界面。未启用桌宠时保留现有关闭应用行为。显式“退出息流”关闭全部窗口，并继续复用已有受控服务关闭与子进程回收逻辑。

托盘提供：打开息流、新对话、收进 Inbox、显示/隐藏桌宠、退出息流。隐藏桌宠与关闭桌宠功能分别处理：隐藏仍可通过托盘恢复，停用后主窗口下次关闭按原有退出语义执行。

桌宠设置独立保存到应用数据目录的 `companion.json`，含启用状态、是否可见、位置、缩放及置顶偏好。使用校验与原子写入，损坏数据回退默认值。保留项目现有用户偏好结构。

## 6. 快速对话与状态同步

单击桌宠展开“新对话”“收进 Inbox”“打开息流”三个操作。新对话展开简短输入框；用户显式发送后由 `main` 复用 `ChatProvider.send` 创建会话并发起请求。完整回复通过“查看对话”进入现有 Assistant。发送本身不强制把主窗口抢到前台。

跨窗口命令带 `requestId`，主窗口接收时去重，并返回接收结果和新会话 ID。输入仅在确认接收后清空；服务未就绪或接收超时则保留草稿，显示重试入口，不自动重复发送。保留已有每会话并发限制和停止流程。

主窗口把经过整理的运行快照交给 Tauri 协调层，协调层缓存最新快照并发事件，桌宠订阅后读取快照。快照带递增修订号，较旧事件不能覆盖较新状态。桌宠重开后仍可取得当前状态，不依赖曾经收到的事件。

快照只包含运行标识、会话 ID、运行阶段、开始时间、简短状态文字和活动任务数，不带 API Key、完整用户内容、工具参数或原始 `reasoning_delta`。摘要从真实 `status/steps` 中取最新有效项，合并空白并限制约 80 字，不为展示另发 LLM 请求。

多任务时优先显示当前选中的运行中会话，否则显示最近启动的任务，并标出其余任务数量。完成反馈短暂显示约 5 秒后回待机；失败保留简短提示与查看入口。点击状态气泡聚焦对应会话。没有任务时不伪造进展。

## 7. Inbox 快速收录

从桌宠或托盘打开 `capture`，无需打开完整主界面。复用现有文字、链接、单文件和 AI 整理逻辑，提交到 `POST /api/inbox/import`。

表单支持粘贴文字或链接、粘贴文件、选择文件和拖入单个文件，沿用现有 20 MiB 文件上限和后台整理语义。默认不读取系统剪贴板，只有用户主动粘贴或选择内容后才接收。

保存期间阻止重复提交。保存成功显示“已收进 Inbox”和“查看内容”，并向主窗口发送带内容 ID 的刷新事件；后续分类与内容去向仍遵循已有服务规则。网络、解析或文件限制错误就近显示，保留输入与已选文件，允许重试。

新收录请求只在用户点击提交后产生；展开面板、恢复窗口和刷新页面不创建卡片。未保存草稿关闭时需要明确处理，不静默丢弃；成功后可继续收录下一条。

## 8. Q 版 Live2D 资源与动作

运行时采用 Cubism SDK for Web 在桌宠窗口内渲染。模型交付应包含 `.model3.json`、`.moc3`、纹理、物理配置及本功能使用的动作/表情文件；SDK 与模型导出版本须兼容，并按官方流程确认发布授权。

建模前需把已选 Q 版重整为适合变形的拆层素材：左右眼与眼皮、瞳孔、眉、嘴、面部、前后发与侧发、躯干、披肩、左右手臂与手、衣裙、左右腿与鞋、星形配饰。补全被遮挡区域，再在 Cubism 中建立网格、变形器和参数，验证转头或动作时不露空白。

动作约定：

| 状态 | 表现与触发 |
| --- | --- |
| idle | 待机呼吸、自然眨眼、克制的头发与披肩摆动 |
| thinking | 对应真实运行状态，轻微歪头或专注表情 |
| success | 对话完成或收录成功时，微笑并小幅点头/挥手 |
| error | 轻微困惑表情，配合可读错误提示，不持续强烈动作 |
| interact | 点击时简短回应；拖动开始与释放不误触快捷操作 |

动作状态与业务状态通过小型渲染接口连接，不把 Cubism 文件名散落到对话或收录逻辑。减少动态效果时停止持续摆动，以静态姿态与文字反馈表示状态；隐藏窗口时停止不必要的渲染。

当前仓库未发现现成 `.moc3`、`.model3.json`、`.cmo3` 或 PSD 模型资源。实际 Live2D 完成验收必须以可加载模型及动作运行结果为准。模型尚未交付时，可使用明确标注的静态姿态开发窗口与业务集成，不将其描述为 Live2D 已完成。

## 9. 安全、可访问性与错误处理

保留本机随机端口、私有令牌与导航来源约束；新窗口只允许本应用拥有的 origin。Tauri 命令按窗口标签和用途校验，桌宠不因此获得通用文件系统、Shell 或任意导航权限。

操作支持键盘焦点、可读名称与 Escape 关闭面板，交互目标至少约 40 CSS px。角色本身可作为有名称的按钮，独立装饰立绘设置空替代文本。减少动态效果设置在所有窗口一致生效，状态不能只靠动画或颜色传达。

后端未就绪时禁用提交并提示连接状态；IPC 失败保留草稿；角色资源失败提供简单静态占位且保留快捷操作；收录或对话失败不影响彼此。保持真实进展和错误，禁止用动画假装任务成功。

## 10. 验收与实施顺序

实施顺序：先验收独立角色素材与首页布局，再完成窗口/托盘生命周期、快速对话与状态同步、收录小窗，最后接入和验收实际 Live2D 模型。

验收至少覆盖：

1. 首页角色在宽屏、窄屏、深浅主题及减少动态效果下清楚展示，不遮挡 Today 原有功能。
2. 主窗口最小化和关闭到托盘后任务继续；恢复后消息与原会话对应；显式退出释放本地服务及窗口。
3. 桌宠拖动、缩放和显示器变化后仍可找回，透明区域不大面积挡住桌面。
4. 快速对话每次显式提交只创建一个会话；接收失败草稿仍在；完成/失败及多任务状态对应真实运行。
5. 快速收录的文字、链接和文件可在主应用找到；重复点击不重复提交；错误后内容仍可重试。
6. 桌宠重开与晚到事件不导致状态倒退；失败状态、资源缺失和服务未就绪可读、可恢复。
7. Live2D 模型真实加载成功，待机/思考/完成动作可切换，减少动态效果与隐藏窗口停渲染有效。

测试覆盖窗口协调、命令确认、事件修订与收录失败恢复等有实际风险的行为；静态立绘替换通过构建、视觉与可访问性检查，不编写仅复述 CSS 实现的测试。
