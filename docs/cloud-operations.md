# 云端账号管理、备份与同步基础

当前仅支持一个后端实例、一个 Uvicorn worker。用户、工作区与业务实体的 ID 持久保存，重启或重新登录不重新分配工作区。

## 账号恢复

在云端相同环境变量、相同持久卷下运行：

```sh
python -m xiliu.cloud.admin create username
python -m xiliu.cloud.admin reset-password username
```

命令会交互输入密码，密码不放在命令行参数中。重置密码会撤销该账号的全部旧会话；资料与累计试用次数保留。网站暂不提供邮件找回密码，用户联系站点管理员恢复。

## 一致性备份与恢复

1. 停止应用接收写入，等待聊天、后台任务及文件解析退出，再备份整个 `/data`。不要只复制单个 SQLite 主文件而忽略运行中的 WAL。
2. 完整保留身份数据库、试用账本、所有工作区数据库、Markdown、附件、索引、任务产物及 `model-settings.enc`。
3. 单独安全保存 `XILIU_CLOUD_MASTER_KEY` 和部署配置。主密钥丢失后无法解密用户模型配置；不要把密钥放入仓库或公开下载包。
4. 恢复到停机的持久卷，保留原主密钥和文件权限，然后启动单实例服务。验证两个账号仅能读取各自资料，附件可下载，原试用余额未重置。不要让两个实例同时写入恢复卷。

## 本次提供的同步基础

每个工作区的 `app.sqlite3` 与 `automation.sqlite3` 保存 `cloud_workspace`、`cloud_entity_versions` 和 `cloud_changes`。变更记录包含实体 ID、递增版本、删除标记及时间，不复制正文、密码或 API Key。

业务表触发器在同一事务内记录直接 API、助手和后台写入；回滚不产生成功记录。已有资料初始化为版本 1，重复加载不会重复播种。模型配置仍使用工作区专属加密文件，成功写入后只记录配置版本；日志失败时还原旧文件。

变更游标是 `(数据库域, seq)`，实体版本按实体递增。当前没有公开同步接口、离线合并或桌面登录，也不会自动上传已有桌面资料。后续实现账号关联与冲突策略时使用这些基础。
