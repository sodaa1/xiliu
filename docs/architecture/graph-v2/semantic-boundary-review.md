# 语义判断与执行保护调整

用户要求：信息充分性尽量由模型判断，减少代码层重复语义拦截，只保留关键保护。

## 已应用的安全子集

- 注册表确认是只读工具，且模型也标记 read 时，允许 scope=all。
- 只读判断不再因自报 confidence < 0.9 或多余 domain 字段不一致而拒绝；工具实际领域以注册表为准。
- 参数 schema、对象来源与存在性、权限、联网限制、写入确认及数据库核验不变。
- 非 Inbox 批量写入不再显示 Inbox 提示。
- 保存无密钥、无原文正文的语义决策摘要（kind/domain/action_id/scope/confidence）及 reason_code，贯穿 verifier 和最终会话记录。

## 用户已批准的分项方案（2026-10-12 已实施）

自动审批认为同时删除对象与参数来源校验会扩大模型驱动写入的范围。原整批补丁没有应用。
进一步修改建议采用以下明确边界，而不是直接放行模型提供的任意参数：

1. **相对时间**：向模型提供带时区的当前时间，由模型解析“明天上午九点”；代码验证输出日期格式、必要时间与时区，不再要求 ISO 日期逐字出现在用户句子中。
2. **标题与名称**：允许模型根据用户要求概括任务标题或生成名称。导入原文和链接仍要求来自用户输入或有效记忆；不得编造原文、链接及附件。
3. **对象指代**：模型可根据工具返回的候选对象和会话记忆选择，代码只接受候选集中的真实 ID；对象不明确时澄清。不得把模型猜测的 ID 直接传给写入工具。
4. **批量范围**：由模型判断用户语义，注册表明确标注哪些写工具支持批量。只对这些工具允许集合参数，其余拒绝；危险操作的人工确认保持。
5. **联网与 AI 功能**：由模型判断本轮请求是否要求相关功能，保留 policy/local_only 和用户明确禁止规则；不再要求特定肯定措辞。
6. **置信度和领域**：取消写操作的固定自报置信度门槛；选择的工具必须在过滤后的清单内，真实权限和读写类型来自注册表。语义歧义由模型返回具体澄清问题。

当前测试中“相对日期与归纳标题”“非固定词语表达整个 Inbox 归类”是上述待批准行为的预先回归测试；在未应用此部分时会失败，保留失败记录，不修改成功标准。

涉及文件：app/executor.py、app/intent.py、app/actions.py、app/dispatch.py、graph/nodes/execution.py、graph/nodes/verifier.py，以及对应集成测试。无安装包集成、无用户内容变更。

## 实施结果

- 相对日期进入模型并提供 current_time；输出验证 ISO 日期及时区。标题/名称可概括，原文、链接等来源校验保留。
- 对象先读取真实候选；非直接匹配时用模型结合记忆消歧，严格拒绝候选集外 ID、重复 ID 和单对象操作的多选。
- 注册表 supports_batch 仅开放现有 Inbox 两个批量工具；读写类型、权限、确认和持久化核验保留。
- 联网/AI 使用明确语义授权标记和可在本轮请求核对的 authorization_quote，不能以发生模型调用代替授权。显式禁止、local_only 与 policy 仍生效。
- 原先两个预置失败已通过；原失败记录保留。118 项回归通过，新增真实候选集成测试后定向 20 项通过；Ruff 和 Pyright 通过。
- DeepSeek Flash 真模型：待办查询、相对时间写入、空 Inbox 批量归类 3/3，检查实际回执与隔离数据库。不是全部 51 条真模型验收。
- 本次未修改安装包。
